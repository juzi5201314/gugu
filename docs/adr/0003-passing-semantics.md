# ADR 0003：传递是浅拷贝，不是 Copy/Clone 门槛

- 状态：已接受
- 日期：2026-08-30

## 上下文

Gugu 要 `&x` 引用传递、标量按值传，但不想把 Rust 的 Copy / move / Clone / 生命周期暴露给用户。GC 上的结构体、句柄若走「非 Copy 就不能 `f(x)`」，等于把心智负担原样请回来。

## 决策

- `f(x)` 永远合法：浅拷贝值表示。位类型独立副本；句柄拷贝指针/头、共享载荷。
- `Vec`/`chan` 的可变状态（len 等）必须在堆对象上，使 `f(v); v.push()` 调用者可见。`string` 可做不可变胖指针。
- `f(x)` 对句柄既不是 `clone`（O(n) 深拷）也不是 `&x`（指向局部槽、可换绑）。
- `f(&x)` 指向绑定槽。逃逸则装箱，不报生命周期。
- 普通函数调用不自动取地址或解引用；`f(x)` 与 `f(&x)` 对用户是可靠信号。方法 `&Self` 可以插 `&p`。
- 没有用户级 `Copy`，没有 move 错误。`Clone` 只表示深拷贝，不是传递许可证。
- 大结构体按值传是 lint，不是类型错误。
- `Vec` 再分配换新 backing，旧切片仍有效（GC），不靠借用检查防悬空。

## 后果

- 用户结构体不会因为「活在 GC 里」就不能按值传。要分享身份，显式传 `&T` 或把 `&T` 放进字段。
- 内部仍可用借用式别名分析做优化；失败则降级到 GC / 多一次拷贝，而不是红色波浪线。
